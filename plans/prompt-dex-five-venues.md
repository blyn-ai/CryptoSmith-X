# Промпт: пять DEX — от замера до UI без прочерков, одним проходом

**Цель одна, и она же приёмка:** на тесте на страницах `/studio/v2/BTC` и `/studio/v2/ETH`
появляются строки dYdX, Synthetix, Vertex, GMX и Drift, и в каждой **все пятнадцать колонок
заполнены** — измеренным значением или выводимым с бейджем.

План и его доводы — `plans/dex-five-venues.md`. Этот файл — как.

**Порядок площадок:** dYdX → Synthetix → Vertex → GMX → Drift. Каждая проходит **весь** цикл
ниже целиком, прежде чем начинается следующая. Каждая — отдельный коммит в `main`; push
деплоит на тест. Первым делом — `git pull`: мигратор теперь отказывается стартовать на
дубле номера миграции (`c979e55`), а номера сегодня уже сталкивались.

- **Образцы.** Книжная площадка без сокета — `BybitPerpMarketData`, `OkxPerpMarketData`, их

- `DeclaredDatasetsAreImplementedTests` проверяет, что каждый объявленный набор имеет своё

## Цикл на каждую площадку

### 1. Замер — первым, внутри того же прохода

Прежде чем писать класс, снять живые ответы и записать с командой и датой, в формате
существующих строк `plans/exchange-roadmap.md`:

- транспорт (REST / GraphQL-субграф / другое), кто хостит, нужен ли ключ;
- закрывает ли снимок один bulk-вызов — сколько инструментов, сколько байт;
- какие из одиннадцати полей площадка публикует и **в каких единицах** (OI в базе или в USD;
  funding за час/год/накопленный; размеры в монетах или контрактах);
- есть ли настоящая книга и на каком транспорте; у гибридов — книга, кривая AMM или сумма;
- **для Synthetix и GMX — публикует ли площадка функцию импакта или спред при размере.** От этого
  зависит, достижима ли приёмка честно (см. «Граница» ниже);
- есть ли в кадре собственное время площадки;
- лимиты: темп, потолок, поведение под нагрузкой.

Срезанные копии живых ответов — в `tests/.../Fixtures/<площадка>/`, с датой снятия.

### 2. Каталог

- [ ] Миграция: `base_url` сегмента — **только измеренный хост**. Бюджет по замеру, с
      `request_budget_source` = `measured` или `documented` и цитатой в `request_budget_note`.
- [ ] Если замер показал, что `market_model` из 0057 врёт про площадку, — **не менять молча**:
      записать в отчёт с замером; это модельное решение владельца.

### 3. Адаптер

- [ ] Клиент + `*PerpMarketData : IExchangeMarketData`, регистрация в `ExchangeWorker.Build`.
- [ ] `Capabilities` — **ровно то, что площадка честно отдаёт.** Не объявлять набор без тела.
- [ ] **Нормализация базового актива.** Страница актива группирует по семейству; если тикер
      площадки (`BTC-USD`, рыночный токен пула, что угодно) не сведётся к `BTC`, строки просто
      не будет на `/studio/v2/BTC` — и это молчаливый провал приёмки. Тот же нормализатор, что
      у остальных; второй не заводить.
- [ ] Книжные (dYdX, Vertex, Drift): bid/ask, размеры топа и глубина — из книги, обычными
      измерениями, тем же кодом полос 10/25/50 bps.
- [ ] Оракульные (Synthetix, GMX): котировка выводится из функции импакта **при заявленном
      размере**, по образцу `AvantisQuotes`; размер едет вместе с цифрой.
- [ ] Тесты на фикстурах: каждое преобразование единиц — отдельный тест. Это класс ошибок,
      невидимых после записи.

### 4. Бейджи — обязательно для Synthetix и GMX

`V2Cells.WithProvenance` ключуется на `market_model`, это верно. **Но тексты бейджей зашиты
под Avantis:**

```
("Q10K", "Executable Avantis quote at $10,000 notional per side (POST /risk/v2/spread) …")
("PYTH", "Pyth oracle feed. Avantis marks positions against this same unadjusted price …")
("CAP",  "Directional capacity from the venue's own availableLiquidity …")
("QUOTE","… found by bisecting POST /risk/v2/spread …")
```

Как только `synthetix-perp` встанет `oracle_vault`, его ячейки получат подсказку, называющую
**чужую площадку и чужой эндпоинт** — ложный провенанс на странице, чья тема и есть
провенанс.

- [ ] Текст бейджа — **на сегмент**, не один на модель: площадка, её эндпоинт, её размер
      котировки, её оракул. Буквы бейджа могут совпадать между площадками; подсказка — нет.
- [ ] Тест: ни одна подсказка бейджа у не-Avantis сегмента не содержит слова `Avantis` и
      эндпоинтов Avantis.

### 5. Включение на тесте

- [ ] Сегмент в `enabled`, наборы, которые площадка объявила, — в `collect`.
- [ ] `collect = true` у всех торгующихся инструментов, как у остальных перпов. Рост базы
      записать в отчёт числом.

### 6. Приёмка площадки — числом, не глазом

Через десять минут после включения:

- [ ] `consecutive_failures = 0` по всем коллекторам сегмента; число `429` за окно,
      **целиком лежащее после включения** (окно короче времени с момента включения — не замер).
- [ ] По `market_snapshot_latest`: сколько строк и сколько NULL в каждом из одиннадцати полей.
- [ ] **Скриптом, не глазом**, отрендеренная `/studio/v2/BTC` и `/studio/v2/ETH`: у строк новой
      площадки — число ячеек с прочерком `—` по каждой из пятнадцати колонок. Ожидание — ноль.
      Приложить вывод скрипта в отчёт.

## Граница: «без прочерков» не разрешает выдумывать

Приёмка — ноль прочерков. **Выполнять её подстановкой нельзя.** Если площадка не публикует
величину и выводить её не из чего — колонку не заполнять, площадку остановить на этом шаге и
написать в отчёте: какая колонка, что именно площадка не публикует, каким замером это
установлено. Решение, показывать ли такую площадку, — владельца.

Конкретно запрещено: `bid = ask = last`; bid/ask из оракульной цены без функции импакта;
глубина из OI; размер топа из оборота; любой ноль на месте отсутствующей величины. Каждое из
этого закроет прочерк и солжёт в ячейке, которая выглядит как измерение.

## Последний шаг, после пятой площадки: популяция ранга

С полными колонками у Synthetix и GMX их **выведенный** спред окажется в одном ранге с
**измеренным** спредом книг — `Verdicts` этой разницы не видит, и зелёный чип встанет над
сравнением двух разных величин. Пустая колонка в ранге не участвовала сама; полная участвует.

- [ ] Популяция ранга режется по `segment.market_model`: выводимые котировки ранжируются
      только между собой. Тот же механизм, что уже режет её по котировке
      (`VerdictScope.PerQuoteAsset`), — ещё одно измерение, не новый механизм.
- [ ] Тест: `oracle_vault`-строка никогда не получает чип в одной популяции с `orderbook`-строкой.

## Чего не делать

- **Не писать непроверенный `base_url`.** Пустое поле честнее догадки.
- **Не менять `market_model` молча.**
- **Не оставлять Avantis-тексты бейджей на других площадках.**
- **Не заводить третье имя модели** без замера, показывающего, что два существующих врут.
- **Не трогать прод.** Приёмка на тесте; прод — `workflow_dispatch` владельца. Прод сейчас на
  `schema 53`, отстаёт; это не твоя задача.
- **Не заводить второй нормализатор активов и вторую формулу полос глубины.**

## Дисциплина проекта

- Сборка `~/.dotnet/dotnet build`; `TreatWarningsAsErrors`.
- Тесты **только по проекту**, не по решению: на решении зависает.
- `?v=N` у статики — ключ кэша Cloudflare, тратится первым запросом. Деплой проверять
  `?probe=$RANDOM`; сожжённый номер перепрыгивать.
- `[hidden]` проигрывает авторскому `display` — правило писать рядом с `display`.
- Dapper: позиционные записи только с ctor точных типов; массивы Npgsql — `System.Array`;
  `IEnumerable`-параметр ломает `unnest`.
- Комментарии — почему, а не что, с числом замера.
- ssh-алиас `csx-prod` ведёт на **тест**.
