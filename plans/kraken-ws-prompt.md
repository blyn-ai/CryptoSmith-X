# Задание: WS-first рынок для Kraken — кэш, буфер, REST деградацией

Репо: `blyn-ai/CryptoSmith-X`, `main`. Прочти: `Connectors/Kraken/*` (весь),
`Connectors/IExchangeMarketData.cs`, `Hub/Ingestion/SnapshotCollector.cs` и
`CollectorLoop.cs`, миграцию 0007. Возможно, параллельно выполняется
`plans/ui-marketdata-prompt.md` (займёт 0008) — свою миграцию нумеруй следующей
свободной; конфликтов по коду с ним нет.

Правила: .NET 10, raw SQL + Dapper, без EF; TreatWarningsAsErrors; тесты без сети.
Принятая архитектура (решение владельца): WS — основной источник живого рынка,
REST остаётся для bootstrap, метаданных, истории и восстановления; REST-поллинг
НЕ удаляется — он деградированный режим и кросс-чек.

## Что строим

Контракт IExchangeMarketData НЕ меняется. Hub, петли, схема, health-модель —
не трогаются. Меняется источник данных внутри адаптера Кракена:

1. **Общий каркас** `Connectors/Streaming/` — БЕЗ кракен-специфики, он
   переиспользуется будущими WEEX/Hyperliquid:
   - `WsConnection` — connect/reconnect с экспоненциальным backoff+jitter,
     heartbeat/ping, ILogger-события; поток сырых сообщений наружу;
   - `MarketCache<T>` — потокобезопасный кэш «символ → (значение, обновлено-когда)»,
     чтение среза, выборка «не старше X».
2. **Кракен-специфика** в `Connectors/Kraken/`:
   - `KrakenWsFeed` — подписка на публичные фиды `ticker` и `book`
     (wss://futures.kraken.com/ws/v1) по списку символов; тикеры кладёт в кэш;
   - `KrakenBookBuilder` — ведение стакана: снапшот + дельты, проверка seq,
     разрыв последовательности → пометить книгу грязной и запросить ресинк.
     Это самый багоёмкий кусок — покрой тестами гуще всего;
   - depth 10/25/50 bps считается из собранной книги В МОМЕНТ ЧТЕНИЯ среза —
     та же математика, что сейчас в REST-пути (кумулятивный notional от mid,
     полоса не покрыта книгой → null; комментарии схемы 0001 — закон).

## Честность кэша — центральное требование

- `GetTickersAsync` отдаёт из кэша ТОЛЬКО записи моложе порога (setting
  `ws_stale_after_s`, сид 30). Устаревший символ НЕ отдаётся → строка снапшота
  не обновляется → received_at стареет → существующая staleness-логика видит
  проблему. Замёрзший WS не должен выглядеть свежим — это главный отказ,
  ради которого всё затевается.
- WS нездоров целиком (нет соединения / кэш массово стар) → адаптер прозрачно
  делает текущий REST-вызов, как сегодня. Петли зелёные, каденция грубее —
  деградация, не падение.
- Кросс-чек: раз в `ws_crosscheck_interval_s` (сид 60) — REST /tickers, сравнение
  mid-цены с кэшем; расхождение > `ws_crosscheck_drift_bps` (сид 50) по символу →
  книга грязная, ресинк, warn в лог. Ловим тихо замёрзшую книгу при живом сокете.

## Конфигурация (всё в базе — стандарт репо)

Миграция (следующий свободный номер): `exchange.ws_url text` (сид для
kraken-futures: 'wss://futures.kraken.com/ws/v1'; null = у биржи нет WS,
адаптер живёт чистым REST) + три setting-а выше (kind='int', description
по-человечески). UI Exchanges/Details подхватит ws_url в форму (поле рядом с
base_url — если ui-промт уже выполнен, добавь туда же; если нет — просто колонка).

## Жизненный цикл

WS-фид стартует при создании адаптера супервизором и гасится его же
CancellationToken-ом (биржу выключили в UI → сокет закрылся). Подписка
обновляется после discovery (новые/делистнутые символы). Никаких фоновых
задач вне адаптера.

## Тесты (фикстурами, без сокетов)

- BookBuilder: снапшот + последовательность дельт → ожидаемая книга; пропуск
  seq → грязная; ресинк-снапшот чинит. Записи реальных сообщений Кракена
  положи в Fixtures/kraken-ws/*.json.
- Depth-математика из известной книги (те же случаи, что REST-тесты).
- MarketCache: порог свежести отсекает старое.
- GetTickersAsync: кэш свеж → срез из кэша; кэш стар → REST-фолбэк (HTTP замокан).

## Definition of done

1. Локальный стек, kraken enabled: у ВСЕХ ~270 инструментов depth_at свеж
   (разброс возрастов ≈ интервалу снапшота, не минута) — покажи селектом
   min/max возраста depth_at до и после.
2. Обрыв WS (ws_url в базе на заведомо кривой + рестарт хаба или reconcile):
   коллекторы остаются зелёными на REST-пути, данные идут. Селектом покажи.
3. Кросс-чек и ресинк покрыты тестами; все тесты зелёные.
4. Один-два коммита в стиле репо, push в main. На проде kraken уже enabled —
   деплой доедет сам, ничего руками не включать.
