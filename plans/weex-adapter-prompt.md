# Задание: адаптер WEEX Futures

Репо: `blyn-ai/CryptoSmith-X`, `main`. Прочти: `plans/architecture.mermaid`,
`Connectors/Kraken/*` (ОБРАЗЕЦ — второй адаптер строится по его подобию),
`Connectors/Streaming/*` (общий WS-каркас — он для тебя и писался),
`Hub/Ingestion/ExchangeWorker.cs` (BuildKraken — гнездо), миграции 0007 и 0010,
комментарии схемы в 0001 (семантика полей — закон).

Правила: .NET 10 (`global.json` пинит 10.0.400 — собирай через `~/.dotnet/dotnet`,
системный SDK на этой машине битый), raw SQL + Dapper, TreatWarningsAsErrors,
тесты без сети на реальных сохранённых ответах. Hub без ключей — только
публичные эндпоинты. Один адаптер = один PR.

## Фаза 0 — разведка (не пиши код, пока не сделаешь это)

WEEX — маленькая биржа, качество её API неизвестно и НЕ предполагается.
Сними живые ответы публичного REST (контракты, тикеры, клины, funding, стакан)
и, если есть публичный WS — его кадры. По итогам напиши в коммит-месседж
короткий вердикт: полнота полей (есть ли mark/index? OI? funding-история?),
лимиты, форма символов. Реальные ответы сложи фикстурами в
`tests/.../Fixtures/weex/*.json` — тесты маппинга строятся на них.

Известное заранее (из комментариев 0001):
- символы вида `cmt_btcusdt` — raw как есть, справочник разрулит
  (проверь, что авторегистрация активов даёт вменяемые коды; кривые —
  чинятся алиасами, seed-алиасы добавь в миграцию, если увидишь нужду);
- `trade_count` WEEX не отдаёт → null;
- quote-семейство скорее всего USDT.

## Фаза 1 — REST-адаптер (обязательная)

`Connectors/Weex/`: `WeexFuturesMarketData` (контракт IExchangeMarketData),
`WeexFuturesClient` (тонкий HTTP, base_url из конфигурации биржи), `WeexDtos`.
Зеркально кракену, включая DepthMath для глубины.

- Миграция (следующий свободный номер, сейчас 0011): сид `base_url`
  (+ `charts_url`, если у WEEX клины на другом пути; `ws_url` — только если
  фаза 2 состоится, иначе null = чистый REST, машина это уже умеет).
- `ExchangeWorker`: ветка `"weex-futures" => BuildWeex(...)`.
- Чего у WEEX нет — честные null/пропуски по правилам схемы (без выдумывания:
  нет OI — строка снапшота не пишется? НЕТ: OI обязателен в снапшоте по схеме —
  если WEEX не отдаёт OI, зафиксируй это в вердикте и СТОП: обсудим схему,
  не обходи NOT NULL хаками).

## Фаза 2 — WS-first (только если разведка показала живой публичный WS)

На готовом каркасе: свой `WeexWsFeed`/`WeexBookBuilder` (протокол дельт у
каждой биржи свой), кэш/health/фолбэк — из Streaming/, поведение как у кракена:
замёрзший сокет не выглядит свежим, REST остаётся деградацией, кросс-чек по
top-of-book. Помни про CPU: кракен-книги уже едят ~40% ядра — если у WEEX
многословный фид, подписывай книги только для инструментов с collect=true
и скажи об этом в коммите.

Если WS мёртвый/огрызок — фаза 2 не делается, это НЕ провал задания:
ws_url остаётся null, REST-путь полноценный.

## Definition of done

1. Локальный стек: weex-futures → enabled в UI → discovery находит инструменты
   (raw-символы как у биржи, канон через справочник), снапшоты/свечи/funding
   пишутся, коллекторы зелёные. Покажи селектами.
2. Фикстуры — реальные ответы WEEX; тесты маппинга зелёные; вся сюита зелёная.
3. Вердикт по качеству API WEEX — в коммит-месседже (полнота, лимиты, WS да/нет).
4. Прод не трогать: включение weex-futures на проде делает владелец в UI.
5. Один-два коммита в стиле репо, push в main.
