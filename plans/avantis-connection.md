# План: подключение Avantis

**Статус источников.** Всё в §1 собрано по документации Avantis и SDK, а не измерено.
В этой папке уже принят другой стандарт: очередь площадок переставлялась по ответам
шестнадцати эндпоинтов, опрошенных живьём, а не по пересказу разведки. Поэтому §0 —
не формальность: до него ни одно число ниже не считается фактом.

## Что такое Avantis

Перп-DEX на Base с **vault-backed** моделью: контрагент — пул ликвидности, а не встречный
ордер. Цену даёт **оракул** (Pyth Hermes/Lazer, Chainlink), а не собственный мэтчинг.
100+ инструментов: крипта, форекс, **акции**, товары, индексы. Есть carry (funding + borrow,
«net rate»), открытый интерес с потолками и утилизацией, комиссии по классам активов,
торговые часы, OHLCV. Читать данные можно без RPC и без web3 — SDK API-first, но v2
требует **ключ API**.

Стакана нет вовсе. Вместо bid/ask — `get_price_impact_spread(pair, position_size, is_long)`:
спред **зависит от размера и стороны**.

## Главный вывод

Подключение Avantis — это на пятую часть коннектор и на четыре пятых вот что:

> Avantis — **первая площадка, у которой нет двух сторон рынка** (и нет дискретного
> фандинга). Схема это уже допускает: 0030 снял `not null` со всех одиннадцати полей
> снимка. Но путь записи — нет: `Ticker` держит bid/ask/mark/index/funding/turnover/OI
> как ненулевые `double`, а `SnapshotCollector` при `NaN` в любом из восьми полей
> пропускает наблюдение целиком (`SnapshotCollector.cs:135-141`). 0030 §A прямо говорит,
> что снятие ничего не меняет, пока сборщики не переписаны.

Этот же путь записи нужен споту (нет фандинга и OI по природе). Это общая работа — в коде,
не в миграции. `plans/exchange-roadmap.md` в строках 37, 60 и 165 ссылается на `not null`
из 0001 и в этом месте устарел относительно 0030.

Второе, что Avantis приносит впервые: **пустое поле, которое пусто по модели рынка, а не
потому что не получили** — и **рынок, который закрыт по расписанию, а не потому что фид
умер**. Сегодня первое различается только комментарием к колонке (прецедент `last_trade_at`
у HL), второе не различается вовсе: страница считает возраст по `received_at`
(`PairPageLoader.cs:82`), и площадка, отвечающая замёрзшим оракулом в закрытую сессию,
покажет пятничную цену как двухсекундную.

## 0. Разведка живьём — до любых решений

Ни одна строка ниже не оплачивается, пока это не измерено и не записано сюда же.

- [ ] Какие хосты реально отвечают публично и без ключа: `api.avantisfi.com`,
      `data.avantisfi.com`, `core.avantisfi.com`. Что именно требует ключ, что нет.
- [ ] Стоимость — **по наборам, не по площадке**: таблица dataset → bulk / per-symbol /
      derived, вызовов на проход. Роадмап ранжирует по «один вызов закрывает N» — это про
      снимок; OI, свечи и импакт могут быть per-symbol при bulk-снимке.
- [ ] Что в каталоге пар: тик, шаг количества, плечо, потолки OI, класс актива.
- [ ] **Какой timestamp** отдаёт API с ценой: время публикации Pyth или время ретрансляции.
      Это ляжет в `venue_ts` и станет якорем свежести.
- [ ] Есть ли у площадки флаг **«торгуется сейчас»** на инструменте/кадре. Если только
      недельное расписание — это точка решения (см. §4), не заранее выбранное правило.
- [ ] OI: единица (количество / USD-ноционал), по сторонам ли, определяет ли площадка total
      как long + short.
- [ ] Funding: отдаётся ли **компонент скоса отдельно от borrow**, или только net; единица
      (в час / в год / накопленная).
- [ ] Параметры функции импакта, которые площадка публикует (для линии gTrade — обычно
      «one percent depth above/below», потолки OI, коэффициенты скоса) — это входы, из
      которых стоимость любого ноционала воспроизводима.
- [ ] Маркирует ли площадка позиции и ликвидации по **неотрегулированному** оракулу.
- [ ] Оборот за 24 часа — есть ли **у площадки** (например, на `data.avantisfi.com`).
- [ ] Есть ли публичная лента исполнений и ликвидаций.
- [ ] OHLCV: чьи это свечи — оракульной цены или исполнений на Avantis.
- [ ] Сокет: есть ли собственный, или единственный поток — Pyth (то есть **не Avantis**).
- [ ] Лимиты: темп, потолок, поведение под нагрузкой — так же, как мерялось по остальным
      шестнадцати.
- [ ] Записать выводы в `plans/exchange-roadmap.md` — Avantis в очереди сегодня нет; там же
      поправить строки 37, 60, 165 про `not null`.

## 1. Как Avantis ложится в снимок

| колонка | после 0030 | что у Avantis | как читается NULL |
|---|---|---|---|
| `bid_price`, `ask_price`, `bid_size`, `ask_size` | nullable | **нет по модели** | `segment.market_model = 'oracle_vault'` |
| `last_price` | nullable | нет без публичной ленты исполнений | «не получили»; появится с лентой |
| `index_price` | nullable | оракул, дословно | значение |
| `mark_price` | nullable | оракул, если §0 подтвердит маркировку по нему; иначе NULL | значение / «не получили» |
| `funding_rate` + `funding_interval_hours` | nullable (0030, 0028) | **нет дискретного платежа по модели** | пара NULL под `market_model` |
| `turnover_24h` | nullable | существует экономически; через API — по §0 | «не получили», без маркера |
| `open_interest` | nullable | по §0: количество или только ноционал | NULL, если количества нет; ноционал → `oi_quote` |
| `depth_*bps` | nullable | нет по модели | тот же маркер |
| `venue_open` (новая) | — | заявление площадки «торгуется сейчас» | NULL = площадка не говорит |

## 2. Что решить до кода

**2.1. Маркер модели — на сегменте и именем модели, не осью.**
`segment.market_model in ('orderbook', 'oracle_vault')`. Объясняет разом четыре пустых
поля котировки и пару NULL фандинга: «не по природе», а не «не получили». На сегменте —
потому что у Avantis книги нет нигде, и потому что NULL-по-модели у спота уже объяснён
сегментом (`kind`). Намеренно не раскладывается на оси «откуда цена / как исполняется /
как устроена ликвидность»: для этого нужна вторая небуковая площадка. Третья модель — третье
имя, одна строка CHECK. Провенанс цены здесь не кодируется (§0: `venue_ts`).

**2.2. Импакт — входы функции, не отсчёты при выбранных размерах.**
Спред Avantis — функция (сторона, ноционал, момент), снапшотная величина. Хранить
опубликованные площадкой входы (OI по сторонам, потолки, параметры глубины — по §0) в
model-specific наборе (2.6). Любой размер воспроизводим потом; выбор размеров — код, не
схема. Сравнение с книгами при равном ноционале — на чтении, обращением функции, **не** в
`depth_*`: те документированы как измерение книги (0035 §A).

**2.3. Фандинг: `funding_rate` не получает ничего.**
Колонка — один платёж лонг↔шорт за интервал. У Avantis платежа нет, есть непрерывный
carry: скос и borrow (обе стороны → LP) — разные величины. Компоненты — в model-specific
набор с единицей в имени: `funding_rate_1h`, `borrow_rate_1h`; `net_rate_1h` — только если
площадка публикует его как своё число. Пара (`funding_rate`, `funding_interval_hours`) =
(NULL, NULL) под `market_model` читается однозначно; 0028 менять не надо.

**2.4. Цены: index — оракул дословно; mark — по §0; last — NULL без ленты.**
`index_price` документирован как «референс от внешних площадок» — оракул это и есть,
переписывается как опубликован. `mark_price` — только если маркировка по неотрегулированному
оракулу подтверждена. `last_price` — прецедент 0035 §A: прокси вместо сделки — нарушение.

**2.5. OI: `oi_quote` в снимок, количество не выводить.**
Добавить `oi_quote` в `market_snapshot(_latest)` — история его уже держит как
опубликованный ноционал (не наш расчёт). `open_interest` у Avantis NULL, если площадка не
даёт количество. long/short — в набор 2.6; total = long + short только если так определяет
площадка.

**2.6. Общая строка + один model-specific набор.**
Граница: в общую строку не добавляется то, что NULL-по-модели для целого класса площадок.
Всё новое у Avantis — входы импакта, OI по сторонам, ставки carry, потолки и утилизация —
один набор `vault_state` (имя и поля — по §0) со своей таблицей, ключ
(инструмент, `received_at`), своя строка `segment_dataset`, своя capability. Так схема уже
живёт с наборами (`open_interest_history`, `liquidation_volume_history`).

**2.7. `venue_open` на наблюдении.**
Булев в `market_snapshot(_latest)`: заявление площадки «торгуется сейчас», NULL = не
говорит. Свежесть получает третье состояние «закрыт»: возраст показывается, не оценивается,
в счётчик заголовка не входит. Календарей, таймзон и праздников не хранить — их мы получим
неверно и проверить не сможем.

**2.8. API-ключ.**
Механика есть: `/opt/cryptosmithx/.env` (600, вне git), `${VAR:?}`, идентичность лимита =
строка `exchange` (0021), ротация как у `POSTGRES_PASSWORD`. Добавить два правила: ключ
только в заголовке из `AvantisClient`, никогда в URL и логах — тестом; capability `auth`
получает значение «key, read-only, held by hub», описание ключа «needs keys we do not hold»
правится. Если §0 покажет, что публичного чтения хватает — ключ не заводить.

## 3. Коннектор

SDK — питоновский; берём **его документацию как спецификацию HTTP-API** и пишем свой клиент
на C#, как для остальных четырёх.

- [ ] `Connectors/Avantis/AvantisClient.cs` — HTTP, лимитер, без web3 и без RPC.
- [ ] `Connectors/Avantis/AvantisMarketData.cs : IExchangeMarketData`
      — `Capabilities` объявляет **только то, что площадка честно даёт**. Никакого depth.
- [ ] Одна строка `exchange`, **один сегмент** `avantis` (`kind = 'perp'`): классы активов
      делят URL, сокет, пространство символов, адаптер и бюджет — по `docs/decisions.md`
      это один сегмент. Класс — свойство инструмента/семейства. Сегменты по классам — только
      если §0 покажет разные хосты/бюджеты или разное существование наборов.
- [ ] `GetInstrumentsAsync` — каталог пар, классы активов, потолки OI.
- [ ] `GetTickersAsync` — `index_price` = оракул, `mark_price` по §0, `last_price` NULL,
      bid/ask/sizes NULL, `open_interest` по единице из §0, `venue_open` из флага площадки.
      **Закрытый инструмент отдаётся в батче с `venue_open = false`, а не опускается** —
      иначе `received_at` замирает и он читается как деградировавший.
- [ ] `Ticker` и `SnapshotCollector` — фаза 2 записи: nullable-поля вместо `NaN`-пропуска
      строки. Общая работа со спотом; без неё ни одна строка Avantis не запишется.
- [ ] `GetOrderBookAsync` → `null` навсегда, и `depth` не объявляется в `Capabilities` —
      прецедент уже есть (fake-адаптер).
- [ ] Свечи оракула → `market_price_candle`, `series = 'index'`, набор `candles_index`.
      `market_candle` — только с лентой исполнений.
- [ ] Набор `vault_state` — писатель по §0.
- [ ] Крест `segment_dataset` — со всем выключенным, что площадка не умеет.
- [ ] `ExchangeWorker.Build` — ветка адаптера. `ws_url` пустой: **у Avantis нашего сокета
      нет**, поток Pyth — это не поток площадки, и подписывать его «live from venue» нельзя.

## 4. Классы активов и торговые часы

- [ ] `asset_family` / `asset_family_member` заводят некриптовые семьи; страница актива и
      список пар это переживают — проверить.
- [ ] **Разделить «код написан» и «включено в production».** Крипто-пары Avantis (24/7)
      включаются до session-awareness. Акции, форекс, товары, индексы — **нет**: закрытые
      часы записались бы в `coverage`/`collector_gap`/счётчик H1 как сбои либо как ложно-
      свежие цены — загрязнение тех самых таблиц, ради честности которых всё делается.
      Гейт — инструментный `collect`, он уже есть.
- [ ] `Freshness` получает состояние «закрыт» по `venue_open = false`.
- [ ] Если §0 не найдёт флага у площадки — решение принимается там: выводить булев из
      расписания площадки с провенансом, или держать такие инструменты на `collect = false`.

## 5. Студия

- [ ] Строка Avantis показывает прочерки там, где сторон нет, **и говорит почему** —
      «у этого рынка нет стакана», как полоса 2 уже говорит «no level book from this venue».
      Источник фразы — `segment.market_model`, не список площадок в шаблоне.
- [ ] Марки MAX/MIN менять не нужно: `PairColumn` не ранжирует last/mark/index; из
      ранжируемого Avantis заполняет OI и turnover — обе сравнимы.
- [ ] Полоса 2 при выборе цены: карточки стакана у Avantis нет и не будет; вместо неё —
      скос OI и потолок из `vault_state`, потому что именно это у него формирует цену.
- [ ] Закрытый инструмент — своё слово, не «degraded» и не свежий возраст.
- [ ] Полоса 5: наборы, которых у площадки нет, красятся штриховкой «не отдаёт вовсе» —
      механизм есть, ничего изобретать не надо.

## 6. Тесты

- [ ] Адаптер не заполняет bid/ask/размеры и `funding_rate` ничем — ни нулём, ни оракулом,
      ни спредом.
- [ ] `Capabilities` не объявляет depth; `DepthCollector` для сегмента не стартует.
- [ ] `SnapshotCollector` пишет строку с NULL в полях котировки, а не пропускает её.
- [ ] `venue_open = false` не считается просроченным вызовом ни в клетке, ни в счётчике
      заголовка; при этом возраст по `received_at` в строке есть.
- [ ] Закрытый инструмент присутствует в батче тикеров (не опущен).
- [ ] `oi_quote` пишется как опубликовано; `open_interest` не выводится делением.
- [ ] Ключ API не попадает в URL и в лог запросов.

## Чего не делать

- **Не выдумывать котировку.** Ни `bid = ask = last`, ни `bid = oracle - spread/2`.
  Отсутствующая сторона — факт о рынке, и он должен читаться как факт.
- **Не писать net rate в `funding_rate`.** Колонка — один платёж лонг↔шорт; carry — другая
  величина с другой единицей.
- **Не выводить `open_interest` делением ноционала на цену.** Хранится опубликованное;
  читатель считает сам, имея обе цифры.
- **Не хранить календари торговых сессий.** Только заявление площадки на наблюдении.
- **Не звать поток Pyth «живым от площадки».** Это оракул, общий для многих; наш признак
  «live» обязан означать «пришло от венью».
- **Не заводить сегмент на каждый класс активов.** Классы делят всё, чем определён сегмент.
- **Не тянуть питоновский SDK в рантайм.** Документация как спецификация — да; зависимость
  на другой язык в хабе — нет.
- **Не начинать с коннектора.** Он самый простой и самый бесполезный до §2.

## Порядок и что чем блокируется

1. **§0.** Без него §1 — пересказ, а не факт.
2. **Решения §2.** Разговор владельца.
3. **Фаза 2 пути записи:** nullable-поля в `Ticker`, сборщик пишет NULL вместо пропуска.
   Общая работа со спотом — в коде, не в миграции (0030 уже снял `not null`).
4. **Миграция:** `segment.market_model`, `venue_open`, `oi_quote` в снимок, таблица набора
   `vault_state`. Одна.
5. §3 коннектор; включаются **только крипто-пары** (`collect`).
6. §4 — `Freshness` «закрыт»; после этого включаются остальные классы.
7. §5 студия, §6 тесты по ходу.

Шаги 3 и 4 независимы. Шаг 5 ждёт оба. Шаг 6 не блокирует 5.
